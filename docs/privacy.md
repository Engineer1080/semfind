# Privacy and local data

semfind processes personal files under roots passed to `semfind index` or under your home directory when you run `semfind init`. With `semfind init --force`, it rescans your home directory and all registered roots. It includes the built-in settings and Linux command catalogs on every scan. The CLI can consult the local `os-release` file to select matching command examples. The app loads model and tokenizer files locally, uses an embedded Python worker over process pipes, and disables ONNX Runtime telemetry. Setup downloads external dependencies and model files. The downloader only requests the pinned model artifacts.

## Files and stored data

- Only regular files with a supported extension are opened. Hidden files and folders, including `.ssh`, are excluded. Named and relative-path exclusions are saved per root. The system bases `/proc`, `/sys`, `/dev`, and `/run` are excluded.
- On Linux, directory and file lookups use `openat2` to reject symbolic links. Descendant file lookup also rejects mount crossings. A selection must be a directory and cannot be a filesystem root. Unreadable files are omitted. Search checks that an indexed file still opens before displaying its result.
- Extraction reads at most 16 MiB per file and caps stored text at 512 KiB of PDF output or 512 Ki Unicode characters of UTF-8 text. `pdftotext` runs with fixed arguments and a bounded read deadline. It receives bytes over stdin.
- Images and videos are indexed by filename and path. If Florence-2 has been set up locally, `semfind init` also reads supported images in the home directory and sends their bytes over a local pipe to Florence-2. A forced rebuild applies captioning to all registered roots. `semfind index ROOT --caption-images` enables captioning for a selected root, and `semfind init --no-caption-images` skips it for one run. Semfind stores the resulting captions and their text embeddings. The caption worker uses only local model files.
- On Linux, `semfind init` also reads registered desktop entries from the user and system XDG application directories. It stores desktop IDs, application names, and searchable descriptions and keywords, including translations in supported catalog languages when present. Desktop entries that are hidden or excluded from the current desktop are omitted. Application results are refreshed on the next `semfind init`.
- With `semfind init` or `semfind index --manpages`, semfind reads excerpts from installed command manuals and lists executable filenames in absolute `PATH` directories. It stores command names and manual excerpts. Binary contents stay unread, and commands appear as text in search results.
- SQLite stores root paths, exclusions, absolute file paths, names, extensions, content hashes, text passages, catalog descriptions, and embedding vectors. Error output can include local paths. The index directory and database are created with modes `0700` and `0600` respectively on Linux. The index is plaintext and its paths and snippets can be sensitive. Keep the index on storage appropriate for the data it indexes.

Run `semfind unindex ROOT` to remove the registered root and its data. A rescan removes entries for disappeared, newly excluded, or unreadable files. SQLite and FTS5 secure deletion are enabled. Storage-level copies, backups, and filesystem snapshots have their own retention. A search result may include old text until its still-readable file is rescanned.
