# COSMIC integration research

[System76's COSMIC Launcher](https://github.com/pop-os/cosmic-launcher) is a Wayland layer-shell frontend. Its [current manifest](https://github.com/pop-os/cosmic-launcher/blob/master/Cargo.toml) depends on both the Pop Launcher protocol and service crates. The [upstream plugin contract](https://github.com/pop-os/launcher#plugin-directories) documents user-local discovery under `~/.local/share/pop-launcher/plugins/<plugin>/`, a `plugin.ron` manifest, optional regex-based routing, and line-delimited JSON requests and responses. Validate discovery and ranking for unrestricted queries on the packaged Pop!_OS version before distributing a plugin.

The MVP ships a search-only catalog of Sound, Display, Network & Wireless, Keyboard, and Power & Battery, based on the [upstream COSMIC Settings labels](https://github.com/pop-os/cosmic-settings/blob/master/i18n/en/cosmic_settings.ftl). The catalog includes IDs, bilingual descriptions and aliases, groups, and desktop metadata. To try it without selecting files, run `semfind index`, then `semfind "Lautstärke ändern" --category settings`.

A desktop integration should verify the installed service and plugin protocol. An independent libcosmic client remains an option if that integration cannot surface general queries. Verify setting deep links against the packaged settings app before enabling explicit open actions.
